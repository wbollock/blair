# ADR-0003: SQLite (modernc) with sqlc and goose

Status: Accepted · Date: 2026-11-24

## Context
Single primary user, small data (tens of thousands of rows). Wants simple
backups and no separate database container (tududi's Postgres container and
missing backups were a pain point).

## Decision
- SQLite via `modernc.org/sqlite` (pure Go, keeps CGo off). WAL mode,
  `foreign_keys=ON`, `busy_timeout=5000`, `synchronous=NORMAL`. DSN uses
  modernc's `_pragma=name(value)` syntax, with a regression test proving WAL is on.
- One writer connection (`SetMaxOpenConns(1)` on the write pool) plus a read pool.
- Type-safe queries generated by `sqlc` from `internal/store/queries/*.sql`.
- Migrations with `pressly/goose`, embedded, forward-only, run at startup after
  a `VACUUM INTO` safety backup.
- FTS5 for search, maintained by triggers.
- Built-in scheduled backups (`VACUUM INTO`, retention N).
- Every user-owned table has `owner_id`; every query filters on it.

## Consequences
- No horizontal scaling; acceptable for the target use. If ever needed, sqlc
  queries are mostly portable to Postgres.
- Backups are a single file copy.
